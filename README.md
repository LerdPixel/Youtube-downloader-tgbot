# YouTube Downloader Telegram Bot

Telegram-бот для скачивания аудио и видео с YouTube. Файлы отправляются прямо в чат.

## Команды

| Команда | Описание |
|---------|----------|
| `/start` | Приветствие |
| `/help` | Список команд |
| `/audio <ссылка>` | Скачать аудио |
| `/video <ссылка>` | Скачать видео |

## Ограничения

- Максимальный размер файла — **50 МБ** (лимит Telegram).
- Видео длиннее **~16,5 часов** не скачиваются.

## Быстрый старт (Docker)

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите токен.

2. Создайте файл `.env` в корне проекта:

```env
SECRET_TOKEN=your_telegram_bot_token
```

3. Соберите и запустите:

```bash
docker compose up -d --build
```

4. Смотрите логи:

```bash
docker compose logs -f
```

5. Остановить:

```bash
docker compose down
```

## Локальный запуск

Требуется Python 3.11+ и **ffmpeg** (нужен для склейки DASH-видео).

```bash
pip install -r requirements.txt
python bot.py
```

## YouTube cookies (опционально)

Если YouTube блокирует скачивание, экспортируйте cookies в файл `yt_cookies.txt` (например, расширением [Get cookies.txt LOCALLY](https://chromewebstore.google.com/detail/get-cookiestxt-locally/cclelndahbckbenkjhflpdbgdldlbecc)) и положите его в корень проекта.

Для Docker добавьте volume в `docker-compose.yml`:

```yaml
services:
  bot:
    volumes:
      - ./yt_cookies.txt:/app/yt_cookies.txt:ro
```

## Локальная версия в браузере

Рядом с ботом есть самостоятельное приложение **YouTube Local**. Оно не использует
Telegram, токен или модули бота. `bot.py`, `yt_whisper.py`, зависимости бота и его
Docker-запуск не меняются. Оба приложения можно запускать независимо.

### Запуск на macOS

Нужны Python 3.11+, [ffmpeg](https://ffmpeg.org/download.html) (включая ffprobe)
и Node.js 20+ либо Deno для полноценной поддержки YouTube. Например, через Homebrew:

```bash
brew install ffmpeg node
./start_web.command
```

Можно также дважды нажать `start_web.command` в Finder. При первом запуске скрипт
создаст отдельное окружение `.venv-web` и установит веб-зависимости. После запуска
откроется [http://127.0.0.1:8080](http://127.0.0.1:8080). Терминал должен оставаться
открытым; остановка — `Ctrl+C`.

Ручная установка и запуск (macOS / Linux):

```bash
python3 -m venv .venv-web
.venv-web/bin/python -m pip install -r requirements-web.txt
.venv-web/bin/python web.py
```

На Windows после создания окружения используйте `.venv-web\Scripts\python.exe`
вместо `.venv-web/bin/python`. Установите ffmpeg и Node.js / Deno в PATH.

Дополнительные параметры:

```bash
.venv-web/bin/python web.py --port 8081 --no-browser
.venv-web/bin/python web.py --download-dir /полный/путь/к/загрузкам
.venv-web/bin/python web.py --save-dir /полный/путь/к/готовым/файлам
```

Сервер слушает только `127.0.0.1`. Приложению нужен доступ к YouTube, интернету
для загрузки зависимостей при первой установке и свободное место на диске.
Сам интерфейс не требует внешних шрифтов, CDN, API-ключей или Telegram-токена.

### Возможности

- Анализ отдельной ссылки YouTube, Shorts или Music: обложка, название, канал,
  длительность, реальные разрешения, аудиодорожки, главы, субтитры и таблица потоков.
- Разбор плейлистов: список видео, длительности и отметки о недоступных роликах;
  скачивание всего списка либо выбранных видео с общими настройками. Ссылки вида
  `watch?v=...&list=...` разбираются как плейлисты; для одного ролика используйте
  ссылку без `list` или кнопку «Разобрать видео» в списке.
- Калькулятор объёма: размер медиафайла для выбранных потоков, качества аудио и
  фрагмента. Оценка обновляется при изменении настроек без повторного обращения
  к YouTube. Приблизительные размеры помечены `≈`; когда данных недостаточно,
  показывается причина. Дополнительные обложки и субтитры в оценку не входят.
- Общий объём и число скачанных файлов, а также итоговый объём каждой загрузки.
  Сумма считается по истории завершённых загрузок, включая впоследствии удалённые
  вручную файлы; это не сканирование всей папки Downloads и не занятое место на диске.
- Три режима: видео со звуком, только аудио, видео без звука.
- Видео: MP4, MKV, WebM или автоматический контейнер; ограничение разрешения и FPS;
  выбор H.264, VP9, AV1 или лучшего доступного кодека.
- Аудио: MP3, M4A, AAC, Opus, Vorbis, FLAC, WAV, ALAC или исходный формат;
  качество конвертации и язык дорожки при наличии нескольких языков.
- Обложка: без обложки, отдельный JPG, встроенная обложка или оба варианта.
  Встроенная обложка доступна для поддерживаемых форматов.
- Субтитры: выбор языков, обычные или автоматические, SRT / VTT;
  встраивание в видео и отдельные файлы. WebM требует VTT для встраивания.
- Скачивание фрагмента по времени или главе; точная обрезка с перекодированием.
- Метаданные, главы, описание, JSON с информацией, своё имя файла.
- Ограничение скорости, число параллельных фрагментов, cookies из браузера
  или файла и прокси.
- Ручное выражение выбора потоков yt-dlp, например `137+140` или `bv+ba/b`.
  Оно заменяет автоматический выбор разрешения, кодека и дорожки.
- Очередь (одна загрузка за раз), прогресс каждого потока, отмена,
  история после перезапуска, отдельные файлы и ZIP со всеми результатами.

Готовые видео, аудио, обложки и субтитры автоматически сохраняются в стандартную
папку `~/Downloads` (на macOS в Finder — «Загрузки»). При совпадении имён добавляется
суффикс ` (1)`, ` (2)` и т. д.; существующие файлы не перезаписываются. Временные
файлы из `downloads-web/<ID загрузки>/files/` удаляются только после успешного
сохранения результата и записи его расположения в историю. В `downloads-web`
остаётся `job.json` с историей. При ошибке сохранения исходные временные файлы
сохраняются. При следующем запуске старые завершённые загрузки тоже переносятся
в `~/Downloads`, после чего их временные копии и старые архивы очищаются.

Ссылки в истории позволяют скачать дополнительную копию через браузер; для
получения файла в «Загрузках» нажимать их не нужно. ZIP создаётся по запросу и
удаляется после передачи ответа браузеру. `--save-dir` меняет папку готовых файлов,
`--download-dir` — папку временных файлов и истории. Ограничения Telegram на размер
и длительность к веб-версии не применяются. История доступна после перезапуска;
незавершённые загрузки автоматически не продолжаются.

Видеопотоки выбираются и объединяются без перекодирования (кроме точной обрезки).
MP4 предпочитает MP4-видео и M4A-аудио, WebM — WebM-потоки. Если указанных
кодека, языка или качества нет, загрузка завершится понятной ошибкой;
для максимально свободного выбора используйте MKV или автоматический контейнер.
Ручной выбор потоков должен быть совместим с выбранным контейнером.
В режиме «без звука» звук удаляется и при ручном выборе комбинированного потока.
Прогресс показывается для текущего потока, поэтому при переходе к следующему
он начинается заново. Конвертация может занимать время без изменения процентов.

FLAC / WAV не повышают качество исходного звука YouTube. При обрезке субтитры
сохраняют исходные таймкоды; для синхронизации короткого фрагмента потребуется
отдельное редактирование. Текущие и запланированные эфиры не поддерживаются.
Набор форматов зависит от видео и ответа YouTube. Все параметры CLI yt-dlp
не дублируются: например, выполнения произвольных команд через интерфейс нет.

Для плейлиста сначала нажмите «Разобрать ссылку», затем настройте результат и
нажмите «Скачать весь плейлист». По умолчанию выбраны все доступные ролики.
Каждый ролик получает собственную запись в очереди; ошибка одного не останавливает
остальные. Можно отменить сразу всю группу. Имена файлов начинаются с номера
позиции в плейлисте (`001 - ...`, `002 - ...`). Сохранение в Downloads и очистка
временных файлов работают для каждого ролика отдельно.

Список плейлиста разбирается без получения всех потоков каждого ролика, поэтому
до скачивания общий размер неизвестен. Для оценки и выбора субтитров, конкретного
потока или аудиодорожки отдельного видео нажмите «Разобрать видео». Общие настройки
пакета (включая обрезку и ручное выражение потоков) применяются к каждому ролику;
недоступное сочетание форматов даст ошибку только у соответствующего видео.
Поддерживаются списки до 10 000 позиций и очередь до 10 000 видео; длинный список
в интерфейсе раскрывается частями по 100 строк. После перезапуска незавершённые
позиции остаются в истории, но автоматически не продолжаются.

На главной странице показываются только три последние загрузки. Плейлист занимает
одну запись; нажатие на него открывает модальное окно только с видео конкретного
запуска. Окно автоматически открывается после постановки плейлиста в очередь.
В нём три списка со счётчиками: «Скачиваются» (включая очередь и обработку),
«Скачались» и «Ошибки» (также отменённые и прерванные). Названия компактные,
подробности видны при наведении или фокусе с клавиатуры. Можно отменить весь
плейлист или отдельное видео, скачать копию результата либо вставить ссылку
повторно. В длинных списках показываются первые 100 позиций с кнопкой продолжения.
Полная история с теми же тремя списками открывается по нажатию на блок загрузок,
«Все», «Открыть историю загрузок» или пункт «Мои загрузки» в меню. Счётчики объёма
по-прежнему учитывают всю историю, а не только три последние записи.

В ссылке плейлиста обязательно должен быть непустой идентификатор после `list=`.
Ссылки YouTube Music автоматически приводятся к стандартному адресу YouTube
с тем же идентификатором. Разбор выполняется встроенным экстрактором yt-dlp.
После обновления исходников перезапустите сервер и обновите страницу. Если
в памяти остался старый сервер без API плейлистов, интерфейс покажет предупреждение
«Нужен перезапуск сервера»; обновления одной вкладки браузера недостаточно.

Если YouTube просит подтверждение входа, выберите браузер, в котором выполнен
вход в YouTube, либо укажите путь к Netscape cookies.txt в блоке «Cookies и прокси»
**до анализа ссылки**. Чтение cookies браузера может потребовать разрешения
системы на доступ к связке ключей; при ошибках закройте браузер или используйте
экспортированный файл. Cookies не гарантируют снятие всех ограничений YouTube.
При наличии `yt_cookies.txt`
в корне проекта путь подставляется автоматически. Cookies и прокси не сохраняются
в настройках браузера и истории загрузок. Обновление только веб-окружения:

```bash
.venv-web/bin/python -m pip install -U 'yt-dlp[default]'
```

Архитектура: `web.py` — запуск, `web_app/server.py` — локальный API,
`web_app/options.py` — проверка настроек и параметры yt-dlp,
`web_app/jobs.py` — очередь и история, `web_app/static/` — интерфейс без сборки.

### Проверки веб-версии

```bash
.venv-web/bin/python -m pip install -r requirements-web-dev.txt
.venv-web/bin/python -m unittest discover -s tests -v
node --test tests/test_downloads.mjs
```

Интеграционные тесты создают короткий тестовый ролик через ffmpeg, скачивают его
через настоящий yt-dlp с локального HTTP-сервера и проверяют результат ffprobe.
Они не зависят от доступности YouTube и не читают Telegram-токен.
